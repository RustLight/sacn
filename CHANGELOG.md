## [0.12.0](https://github.com/RustLight/sacn/compare/v0.11.1...v0.12.0) - 2026-11-26

### Breaking changes

- Require Rust 1.88 or later ([#123](https://github.com/RustLight/sacn/pull/123))
- Source names are limited to 63 bytes, so they stay null-terminated as E1.31 requires; longer names now return an error ([#76](https://github.com/RustLight/sacn/pull/76))
- Sources created with `SacnSource::new_v4`/`new_v6` bind an ephemeral port instead of 5568, so they no longer take unicast traffic meant for a receiver on the same host ([#84](https://github.com/RustLight/sacn/pull/84))
- `SourceDiscovered` is only raised when a source is new or its universes change, not on every discovery packet ([#97](https://github.com/RustLight/sacn/pull/97))
- Stream termination is honoured on preview data, and only Null START Code data (not alternate START codes such as 0xDD) keeps a source from timing out ([#99](https://github.com/RustLight/sacn/pull/99))
- Errors from the source's background thread are reported through the `log` crate instead of `println!`, behind a new default-on `logging` feature ([#94](https://github.com/RustLight/sacn/pull/94))

### Added

- Support for the Force_Synchronization option ([#83](https://github.com/RustLight/sacn/pull/83))
- `terminate_stream_to`, for terminating streams sent to receivers by unicast ([#90](https://github.com/RustLight/sacn/pull/90))
- Sources can be created on platforms that don't support port reuse ([#71](https://github.com/RustLight/sacn/pull/71), by @DAlexanderNZ)

### Changed

- The packet types in `src/packet.rs` are written out directly instead of generated by single-use macros, so rustfmt and Clippy now check them. No API change. By @deltronix ([#58](https://github.com/RustLight/sacn/pull/58)), landed in [#115](https://github.com/RustLight/sacn/pull/115)

### Fixed

- Synchronised data is held separately per universe and START code, so 0x00 and 0xDD data no longer overwrite each other ([#96](https://github.com/RustLight/sacn/pull/96))
- Synchronised data is acted on immediately until the first sync packet arrives ([#98](https://github.com/RustLight/sacn/pull/98))
- Synchronisation universes are tracked separately from data universes ([#91](https://github.com/RustLight/sacn/pull/91))
- Sync packets on universes the receiver hasn't registered are accepted ([#73](https://github.com/RustLight/sacn/pull/73))
- Data and sync packets are no longer sent on the discovery universe ([#78](https://github.com/RustLight/sacn/pull/78))
- Universe discovery: no empty pages are sent ([#95](https://github.com/RustLight/sacn/pull/95)), repeated pages aren't stored twice ([#80](https://github.com/RustLight/sacn/pull/80)), and discovered sources are kept for two discovery intervals ([#79](https://github.com/RustLight/sacn/pull/79))
- Valid packets are kept when another source has timed out ([#81](https://github.com/RustLight/sacn/pull/81)), and every source is checked for timeouts when `announce_timeout` is set ([#85](https://github.com/RustLight/sacn/pull/85))
- Parsing reads only the bytes of the received datagram ([#77](https://github.com/RustLight/sacn/pull/77)), rejects PDUs shorter than their fixed fields ([#75](https://github.com/RustLight/sacn/pull/75)), and checks the length of `data_buf` correctly ([#67](https://github.com/RustLight/sacn/pull/67), by @bruingineer)
- Creating a source returns an error instead of panicking when its socket can't be created ([#82](https://github.com/RustLight/sacn/pull/82))
- Terminating a source terminates every universe even if one fails, and `Drop` no longer panics ([#86](https://github.com/RustLight/sacn/pull/86))
- TTL and multicast loop settings work on IPv6 sources ([#88](https://github.com/RustLight/sacn/pull/88))
- Receiving no longer recurses, so a long run of ignored packets can't overflow the stack ([#63](https://github.com/RustLight/sacn/pull/63), by @bruingineer)
- The `simple-receiver` example handles short frames and lays out rows correctly ([#89](https://github.com/RustLight/sacn/pull/89))
